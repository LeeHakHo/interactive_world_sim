# flow-warp 渲染臂(can_dual 双机位):治糊,第 0 帧纹理搬运

> 背景与讨论记录见活文档 `FLOW_WARP_REPR_LOG.md` §1-3(用户 2026-07-14 拍板"今晚做")。
> 先例:`exp_scel_flow_warp_render.py`(v3 方块,单机位,判决=简单纹理上不赢、战场在强纹理物体)、
> `footprint_warp.py`(SAM2+Umeyama,备用的刚体拟合路线)。can 的可乐罐 = 强纹理,正是判决说的战场。

## 1. 设计(M1,今晚)

- 在 `exp_scel_dualview_dit_formal.py` 加第四臂 `COND=flowwarp`:
  1. **warp 场**:复用 `cube_warp_grid` 的思路(48 个物体点,当前位置处高斯 splat 反向位移、除以权重、
     掩码=点足迹),**像素域**对第 0 帧做掩码局部搬运(`warp_rgb_masked` 同款),每机位独立;
     未跟踪区域(背景/机械臂)保持第 0 帧。
  2. **网络吃什么**:在 flow 臂的条件图(3 通道)基础上,把"搬运后的图像"经 VAE 编码成 latent 追加为
     输入 token(与 z0/prev 并列的第三组 token,加 type embedding),输出改为**对搬运 latent 的残差**
     (pred = z_warp + out),让网络只补洞/接缝/光照,不重画物体。
  3. 训练协议与 flow 臂完全一致(60 轮、同损失、同数据划分、同评估);机器人+人手混训照旧。
- **判据**:与 flow 臂(0.256/0.279)同口径比 obj-LPIPS;另加眼检锐度(抽帧对比罐子纹理);
  20 帧主表 + 44 帧压力测试(warp 的优势应随时长放大——第 0 帧纹理不衰减)。
- 先 seed 0 拿信号;obj-LPIPS 赢或眼检明显更锐 → 补 seed 1/2;都不赢 → 如实记入活文档舍弃节。

## 2. 已知风险(先例教训)

- 全局 warp 毁未跟踪区 → 必须掩码局部(先例已验证)。
- 遮挡:机械臂挡住罐子时,第 0 帧搬来的像素会"穿透"手臂 → 残差网络要能盖回去;若成为主要伪影,
  后续接可见性通道(表示升级候选 2)。
- 罐子旋转时背面露出:第 0 帧没有背面纹理,搬运无源 → 残差网络补;记录此类失败帧。
- ② 预测驱动时 warp 场随预测误差变形 → M1 先用真实运动(replay)判"渲染上限",赢了再接端到端。
